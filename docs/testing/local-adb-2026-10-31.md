# Built-in local ADB preview validation

## Scope

Version 0.1.0-beta.2 (version code 3) adds temporary on-device wireless ADB
pairing and permission grants. Android Developer options, Wi-Fi and explicit
pairing are still required. No computer or separate Shizuku installation is
needed for this setup path. ADB disconnects before direct diagnostic reads;
Wireless debugging can then be disabled.

The user reported a Pixel 9 Pro and that collection worked after plugging in.
Their Android version and raw failing output were not confirmed. The fractional
discharge parser regression and its primary-source evidence are recorded in
[parser-counter-2026-10-31.md](parser-counter-2026-10-31.md). This is a confirmed
valid-format trigger for the reported error, not a physical-device reproduction.

## Regression guarantees

- Setup tests exercise input validation, the fixed own-package permission grants,
  failures, cancellation and closure before direct verification.
- Protocol integration checks queued data at EOF and unsigned single-byte reads.
- Process tests exercise complete output, timeout, cancellation during a read,
  and cancellation before the IO dispatcher starts the read.
- Access selection tests require verified direct access to take priority over
  Shizuku, retain the old preference before verification, and allow Shizuku when
  the direct permission has been revoked.
- Android instrumentation checks loopback access, native matching/mismatching
  pairing codes and timeout/closure of a stalled TLS pairing socket.

The direct-access preference is stored in app-private settings only after actual
battery and power diagnostics succeed. Pairing codes and ADB credentials remain
temporary in-memory data.

errors or skipped tests. The new access-selection tests first failed compilation
because `directPreferred` was not implemented, then passed after the verified
preference was wired into state, live reads and cold-start access selection.

core branch coverage remains **77.79%**, below the team's 80% branch target.

The final access-selection code review approved the change after removing an
unnecessary Shizuku binder wait for verified direct users. The security review
found no privilege or secret-persistence issue. If usage access alone is later
revoked while DUMP remains, direct reads can fail until permissions are restored;
availability retains the existing DUMP-based check for compatibility.
